# 使用手册

当前 **0.8.0** 登记 **Epic + Steam + 37 类科研来源，共 39 项**。平台登记、DNS 候选和实际下载可用性分别显示，请以本次验证结果为准。

## 三种使用方式

**Steam 官方缓存接管**从本机 Steam 下载日志发现精确服务器域名。管理员启动助手、刷新服务器并启用后，hosts 将所选域名送到 `127.0.0.23` / `::1` 的本机 80/443 转发入口，上游强制 IPv6，不依赖 Clash。HTTPS 保留原始 TLS、站点证书校验和 HTTP/2。详细操作见 [Steam 使用说明](STEAM.md)。

**Epic/科研来源自动接管**适合 Epic、浏览器和已经通过 Clash 联网的下载客户端。选择图标和服务后启动，仍在原客户端操作，不需要每次复制链接。它修改受管理的精确域名规则；本版支持本机 Clash for Windows 规则模式，其他 Clash 衍生客户端未作兼容承诺。

**手动文件下载**适合已经取得 HTTPS 文件直链的科研资料。粘贴直链并开始下载即可，不要求开启 Clash。网页介绍页可能返回 HTML，不能视为 PDF 或压缩包下载成功。签名地址也会过期；本软件不会代替原网站登录。

## Epic/科研来源自动接管步骤

1. 确认原客户端能够通过现有 Clash 正常联网。
2. 点击平台卡片，也可在左侧列表或搜索框寻找来源。
3. 查看服务说明和登记域名，选中服务。一次只接管一个服务组，切换时以实际接管状态为准。
4. 查看上游列表并启动接管。没有可用 IPv6 的来源会失败，不会换用 IPv4 假装成功。
5. 在原客户端开始下载；切换后将已有任务暂停再继续，以重新建立连接。
6. 点击“恢复配置”停止接管；正常退出也会尝试恢复本程序管理的配置。

同域名下的网页请求也受规则影响。选择平台不等于自动发现所有临时对象存储域名。遇到新域名先诊断，不要随意加入未知服务器。

## Steam

1. 停止/退出助手，右键 EXE“以管理员身份运行”。原有其他工具的 hosts 记录会保留；遇到同域名冲突时先在原工具中停止对应服务。
2. 在 Steam 中开始所需游戏下载或更新，再在助手中选择 Steam，点击“刷新下载服务器”。
3. 选择已发现的官方缓存服务，查看上游 IPv6，点击“启动 IPv6 接管”。没有可用节点时会提示失败，不回退 IPv4。
4. 在 Steam“暂停 → 继续”，让旧连接重建。下载中若出现新服务器，再刷新、重新应用服务并重建连接。
5. 点击“验证 Steam 下载链路”。结果核对真实块长度、类型和传输参照哈希，以及助手链路；实际 Steam 进程是否使用回环入口仍需对应客户端连接证据。
6. 用完停止/恢复，或正常退出。助手删除自己的管理块，保留其他 hosts 修改；发生恢复冲突时按提示核对备份。

目前接入官方 `cacheN-region.steamcontent.com` 精确域名；原软件国区 CDN 镜像未接入。Steam 登录、商店、游戏联机、UDP 和未知下载域名不在保证范围内。软件不修改下载地区、账号或凭据。

2026-10-05，最终构建已验证管理员实际 Steam 下载：25.452 秒、22 次采样中，Steam 回环与助手反向连接各观测 120 次，助手公网 IPv6 观测 120 次、IPv4 0 次，六个官方缓存内容流增加 250,120,379 字节。8 项链路通过；立即停止约 0.038 秒，6 条活动连接归零，hosts 原哈希恢复。观测次数不是唯一连接数，也不证明整个 Steam 都只用 IPv6。

最终构建固定 IP 和拉黑检查已通过，原策略已恢复；候选首次停止暴露的 hosts 替换占用也如实保留。最终版先关闭对应连接，再执行 Windows 最多 3 秒原子替换重试，已经复验。真实内容块的参照 SHA256 非 Valve 发布者校验值，未解密最终游戏文件。最终洁净源码测试为 67 个顶层、115 项含子测试通过，2 项显式跳过，go vet 通过。证据和 EXE 哈希见 [验收记录](acceptance/2026-10-05.md)。节点及操作见 [Steam 文档](STEAM.md)；参考软件的分析见 [原软件只读分析](ORIGINAL-SOFTWARE-ANALYSIS.md)。

## Epic / Unreal Engine

选择 Epic Games，启动接管后在 Epic Games Launcher 中下载 UE 引擎或游戏。运行功能验收会请求一个真实 UE 数据块，校验大小、SHA256、解压内容 SHA1，并检查规则和 IPv6 出站。

数据块通过只证明测试时对应 CDN 链路可用。完整 UE 安装还可能访问认证、清单和其他服务，不能把一次测试视为整套引擎下载已完成或全机没有 IPv4。

## 来源检测与实际文件

“来源检测”可筛选名称、分类和状态。“重新检测”刷新相关 DNS 缓存并显示逐域名结果。“验证实际文件”跳到手动下载页并填入公开样本；没有样本时填写自己有权限访问的文件直链。

点击“开始 IPv6 下载”才会建立完整下载任务。预期 SHA256 为可选项，优先填发布者提供的值。不填写时仅计算所得文件的哈希；重复下载哈希一致不等于官方校验通过。

任务支持暂停、继续/重试和详情查看。断点续传取决于服务器 Range/校验器；服务器变化或不支持断点时不能保证接续原内容。

## 上游 IP 固定和拉黑

- 候选来自当前 DNS，显示 IPv6 和解析目标；候选存在不等于实际连通。
- 固定后，该域名新连接只使用有效固定候选。地址不再出现在 DNS 中时拒绝使用。
- 拉黑排除有问题的候选；全部拉黑时停止连接，不回退 IPv4。
- “恢复自动”取消固定，但保留黑名单；需要另行解除黑名单。
- 改变策略可能断开受影响的旧连接，客户端应重新连接。

arXiv 两个明确登记域名使用已实测的 Fastly 双栈入口，仍以原域名进行 TLS 校验。PMC/NOAA 特定匿名云对象在手动下载时可转换成同一官方桶的双栈地址；签名链接不改写，浏览器 HTTPS 不被解密改写。

## 失败原因和处理

| 结果 | 含义和下一步 |
|---|---|
| 未查到 IPv6 | DNS 没有可用公网 AAAA；重测或使用同一资源的官方双栈入口，不能随意替换第三方 IP |
| 域名不存在 | 当前 DNS 返回 NXDOMAIN；核对拼写、服务域名和逐服务证据 |
| DNS 超时/失败 | 加密 DNS IPv6 链路未成功；检查本机 IPv6 与网络线路后重测 |
| 连接超时 | 有候选但路由/TCP/TLS/读取未成功；刷新 DNS、检查固定节点和黑名单 |
| TLS 失败 | 原站证书或握手失败；不要关闭证书校验 |
| 403 / 需授权 | 原网站限制、身份验证或访问挑战；取得已有权限的有效链接 |
| 404 | 资源不存在；从原站取得新链接 |
| 429 | 服务端限流；稍后重试并减少并发 |
| 需文件验证 | 域名检查不足；需要实际文件样本 |
| 格式/哈希失败 | 可能是 HTML 错误页、过期链接或文件变化；核对原站信息 |
| 无可用节点 | 固定/黑名单排除了所有候选；检查策略后重试 |

## pip / Conda 等客户端

支持 HTTP 代理的工具可显式使用 `http://127.0.0.1:17891`。例如仅对一次下载生效：

```powershell
python -m pip download six --proxy http://127.0.0.1:17891
```

只有登记域名受到允许。自建镜像、其他频道、重定向存储和依赖域名需逐项核对。软件不自动修改 pip、Conda 或浏览器全局代理。

## 恢复、升级和本机文件

先点击“恢复配置”并正常关闭旧版，再替换 EXE。首次启动将内嵌引擎提取到 `%LOCALAPPDATA%\EpicIPv6Helper\native-0.8.0`；单文件分发不代表运行时不写文件。

运行配置与备份位于 `%LOCALAPPDATA%\EpicIPv6Helper\runtime`，默认下载目录为 `%USERPROFILE%\Downloads\IPv6科研下载`。异常结束后重新启动并执行恢复。出现恢复冲突时保留备份，根据提示核对，避免覆盖自己后来修改的规则。不要把完整运行目录提交到公开 Issue。
